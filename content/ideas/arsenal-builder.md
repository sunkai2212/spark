## 一句话

把 aiHot 的五项可迁移原则抽象出来，移植到审美和跨学科知识的刻意积累上。

## 起源：从 aiHot 到 Arsenal Builder

### 第一步：拆解 aiHot 的本质

深度拆解了 [aiHot Skill](https://github.com/KKKKhazix/khazix-skills/tree/main/aihot)，从中抽象出五项可迁移原则：

| 原则 | aiHot 的做法 | 可迁移版本 |
|------|-------------|-----------|
| **精选优先** | 默认走精选模式，用户必须明确说「全部」才给全量 | 进入任何新领域，先找信任的筛选源 |
| **稳定认知框架** | 五分类体系（模型/产品/行业/论文/技巧） | 先把领域拆成 4-6 根认知柱子，再填内容 |
| **加工深度分级** | 日报（成品）/ 精选流（半成品）/ 全量（生肉） | 学习素材必须标注加工深度，默认给成品或半成品 |
| **交互面模糊 × 后端精确** | 用户说「今天 AI 圈有什么」，后端精确路由 | 允许模糊自然语言输入，但后端组织必须结构化 |
| **护栏来自踩坑** | 每条规则都是 Agent 真的犯过错的记录 | 先跑一个月再定规范，不第一天设计完美规则 |

### 第二步：关键洞察

受到卡兹克在 2026-05-18 发布的内容创作方法论启发：

> 「如果你同时懂喜剧的节奏、电影的叙事、建筑的空间感、历史的周期性，你面对同一条新闻的时候，你能调用的武器库就是别人的五倍十倍。」

三层创作公式：**获取信息 (30%) → 找角度 (60%) → 创作 (10%)**。aiHot 解决了第一层，但真正产生差异的是第二层——而第二层的力量来源正是跨学科知识。

### 第三步：关键纠正——要方法论，不要产品

最初的本能反应是「在 aiHot 上建新平台」。但sunka 纠正了这一点：**不是做产品，是提炼方法论**。审美才是真正的护城河；工具不制造同质化，个体经验的总和才是差异化来源。

## 核心哲学

**信息的价值不取决于信息本身，而取决于它进入你认知系统的精确时刻和精确位置。**

本 Skill 不做三件事：
- 不替你判断什么是美的、什么是对的
- 不给你一堆链接然后说「去看吧」
- 不假装积累可以速成

只做一件事：**在你和任何一个陌生领域之间，搭建一座最短的桥。**

## 路由系统：五个分支

| 用户在说 | 走的分支 |
|---------|---------|
| 「我想学电影叙事」「建筑空间怎么入门」 | **分支 A：建框架（默认）** |
| 「给我推荐几本书」「有什么好的入门资源」 | **分支 B：精选资源** |
| 「喜剧节奏和建筑空间有什么共同点」 | **分支 C：跨领域结构类比** |
| 「看看我的武器库」「帮我盘点一下」 | **分支 D：武器库审计** |
| 「我刚看到一个有意思的镜头，帮我记下来」 | **分支 E：洞察卡片** |

**设计原则**：默认建框架，不是扔资源。

## 分支 A：建框架（默认路径）

1. **定位用户坐标**：零基础？有印象但不成体系？最近一次被这个领域触动是什么时候？
2. **提炼核心维度框架**：找出 4-6 根认知柱子——查经典教材目录、高手访谈、做跨领域类比、从案例反推
3. **给一个入口点**——不是书单，就一个。标准：足够短、足够好、足够典型
4. **设定最小可执行练习**——「做了」才算，不是「理解了」

## 分支 B：精选资源

资源分三级，每次最多给 3 个：

| 等级 | 标签 | 何时给 |
|------|------|--------|
| 🥇 成品 | 已被高手拆解分析过 | 用户刚入门时 |
| 🥈 半成品 | 被筛选但未深度整合 | 用户已有框架后 |
| 🥉 生肉 | 原始作品 | 用户有判断力后 |

## 分支 C：跨领域结构类比

类比质量分三级：

| 等级 | 标志 |
|------|------|
| ✅ 结构同构 | 底层模式一样，表面完全不同——「ASML 从飞利浦边缘部门变成全球咽喉」→「边缘反噬中心」 |
| ⚠️ 表面相似 | 用词一样但逻辑不通——「AI 就像一把刀」，什么都能切，什么都没说 |
| ❌ 强行牵强 | 为了类比而类比——「神经网络就像大脑」，不是类比，是命名的来源 |

## 分支 D：武器库审计

定期盘点：已涉猎领域、框架完整度（🟢/🟡/🔴）、最近一次练习时间、偏科警告、建议下一个涉猎领域。

## 分支 E：洞察卡片

记录「有感觉」的瞬间。模板：**感觉**（先写感受，不分析）→ **拆解**（哪个维度？什么手法？）→ **连接**（跟之前的什么记录有呼应？）

## 实践协议

| 领域类型 | 练习四步法 |
|---------|-----------|
| 叙事/文字类 | 拆解 → 模仿 → 对比 → 创作 |
| 视觉/空间类 | 观察 → 标注 → 分析 → 重构 |
| 声音/节奏类 | 闭眼听 → 找模式 → 去掉它（感受缺失）→ 配别的 |
| 抽象/理论类 | 人话复述 → 找日常例子 → 教别人 → 应用到新场景 |

## 十项护栏

- 不要用户说「想了解 X」时扔一堆链接
- 不要一次给超过 3 个资源
- 不要用学术黑话解释概念后再用「说白了」翻译
- 不要在没有结构同构时强行类比
- 不要跳过实践环节
- 不要假设用户有前置知识
- 不要在用户还没消费完第一个入口时推荐第二个
- 不要替用户做审美判断
- 不要在没有问过「你最近一次被这个领域触动是什么时候」之前就建框架
- 不要把洞察卡片当成一次性记录

## 技术方案

- Skill 文件：独立的 `SKILL.md`，遵循 Agent Skills 开放标准
- 兼容 Claude Code / Codex / Cursor / OpenCode
- 无后端、无数据库——纯方法论文本
- 建议用户自己维护武器库（Obsidian / Logseq / 火花站均可）
